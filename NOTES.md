# Нотатки: C для embedded

## const
Означає «це значення не можна змінювати». Компілятор видасть помилку, якщо спробувати.

```c
const int max_speed = 100;      // константа
void print(const char *s);      // функція обіцяє не змінювати рядок s
```

Навіщо в embedded: константи (таблиці, рядки) компілятор може покласти у флеш-пам'ять замість RAM, якої на мікроконтролері мало.

## static
Має два різні значення залежно від того, де написано.

**Усередині функції:** змінна живе весь час роботи програми і зберігає значення між викликами.
```c
int counter(void) {
    static int count = 0;   // ініціалізується один раз
    count++;
    return count;           // 1, 2, 3, ...
}
```

**На рівні файлу:** змінна або функція видима тільки в цьому .c-файлі, як private.
```c
static int uart_errors = 0;   // інші файли не бачать і не можуть зламати
```

Навіщо в embedded: так ховають внутрішній стан драйвера від решти програми.

## volatile
Каже компілятору: «це значення може змінитися будь-коли не з мого коду, тому щоразу читай його з пам'яті й нічого не оптимізуй».

Коли потрібен:
- **регістри заліза**: значення в регістрі UART змінює сам мікроконтролер;
- **змінні, які змінює переривання**: компілятор не знає, що функція переривання може викликатися будь-коли.

```c
volatile bool data_ready = false;   // ставиться в перериванні

void UART_IRQHandler(void) { data_ready = true; }

while (!data_ready) { }   // без volatile компілятор міг би зробити вічний цикл
```

## Стек vs heap

| | Стек (stack) | Купа (heap) |
|---|---|---|
| Що там | Локальні змінні функцій | Пам'ять від malloc |
| Хто звільняє | Автоматично при виході з функції | Програміст через free |
| Швидкість | Дуже швидко | Повільніше |
| Ризик | Переповнення стека (глибока рекурсія, великі масиви) | Витоки, фрагментація |

Навіщо в embedded: на мікроконтролерах heap майже не використовують. Пам'яті мало, а через фрагментацію malloc може раптово повернути NULL посеред польоту. Замість цього використовують статичні масиви фіксованого розміру, наприклад кільцевий буфер.

## Важливо
Ніколи не повертати з функції адресу локальної змінної: після виходу з функції ця пам'ять на стеку вже «чужа».
```c
int *bad(void) {
    int x = 5;
    return &x;   // помилка: x знищено після return
}
```
